MASTER PROMPT — UI/UX + PACKAGING QUALITY SYSTEM

You are building a high-end productivity application. The functional system (time engine, routines, domains) is already defined separately. Your task here is not just implementation, but world-class product packaging and user experience execution.

This part is as important as the logic itself.

1. CORE REQUIREMENT (MOST IMPORTANT RULE)

The success of this product depends more on how it feels than how many features it has.

If the UI is:

cluttered
inconsistent
visually generic
or cognitively heavy

the product is considered a failure even if logic is correct.

2. DESIGN SOURCE OF TRUTH (STRICT RULE)

The user has provided reference images for UI direction.

Absolute requirement:

You must:

visually study all provided designs
extract their:
color system
spacing logic
typography style
softness / sharpness balance
card shapes
interaction feel
motion style (if implied)

Then:

Reconstruct the UI so that it matches the same design language, not just “similar vibe”.

Critical rule:

Do NOT reinterpret the style into something “standard UI best practices”.

You are not designing freely.
You are translating a visual identity into a working product.

3. UI PRINCIPLES (NON-NEGOTIABLE)
3.1 Absolute visual clarity

At any moment:

user should understand what to do within 1 second
no visual competition between elements
3.2 Single focal object principle

Every screen must have:

one dominant element (task / action / state)
everything else is secondary or hidden
3.3 No visual noise tolerance

Strictly avoid:

dense dashboards
small unreadable data clusters
unnecessary icons
competing widgets
information overload screens

If something is not directly needed for the next action → hide it behind interaction.

3.4 Emotional UX design (critical)

The UI must feel:

calm
premium
slightly playful (as per reference images)
non-punitive
non-judgmental
smooth and continuous

Never:

red error states that feel like failure
aggressive warnings
“you are behind” type language or visuals
4. PACKAGING = CORE PRODUCT VALUE

Packaging means:

How the entire system feels as a continuous experience, not how screens look individually.

You must ensure:

4.1 Flow continuity

When user moves between:

NOW → TODAY → DOMAINS

The transition must feel:

seamless
non-jarring
like one continuous space

No “app switching feeling” inside the same app.

4.2 Micro-interactions matter more than features

Every action must feel:

responsive
soft
intentional
satisfying

Examples:

starting a block feels like entering focus mode
pausing feels like “holding time”
resuming feels like “continuing flow”
4.3 Motion system (if applicable)

Use motion to:

guide attention
not decorate

Motion should:

be subtle
smooth
non-distracting
reinforce continuity of time
5. UX FLOW REQUIREMENTS
5.1 Default state (app open)

User sees ONLY:

current action
one primary button (start / resume / pause)
next action preview (minimal text)

Nothing else.

5.2 Interaction philosophy

User should NEVER:

search for what to do
interpret dashboards
plan manually during execution

The system always answers:

“What is the next smallest action I should take right now?”

5.3 Deep layers (hidden complexity)

Advanced features exist but must be:

behind intentional taps
not visible in default UI

Examples:

full routine editor
domain deep tracking
consistency breakdown
system settings
6. VISUAL STYLE REQUIREMENT (CRITICAL)

The app must visually match the provided references exactly in:

color palette
gradients (if used)
spacing rhythm
border radius style
shadow softness
hierarchy balance
typography weight system
Rule:

Do NOT replace the design language with generic UI frameworks styling.

If a choice must be made:

prioritize matching the reference visuals over standard UI conventions.

7. CONSISTENCY VISUALIZATION (IMPORTANT UX DETAIL)

Consistency must NOT appear as:

graphs
charts
numbers-heavy dashboards

Instead:

subtle states
simple labels
intuitive signals

Examples:

“Strong rhythm”
“Stable rhythm”
“Recently active”
“Quiet period”

This should feel like:

reading a status, not analyzing data.

8. USER EMOTIONAL EXPERIENCE TARGET

The app must consistently make the user feel:

“I know exactly what to do”
“Nothing is overwhelming”
“I am always on track even if I pause”
“I can always continue without guilt”

It must NEVER feel like:

falling behind
breaking system rules
failure accumulation
9. FEATURE COMPLETENESS REQUIREMENT

You must ensure:

no part of the system described in the product spec is missing
no feature is partially implemented
no feature is shown in UI without being usable
no hidden inconsistencies between:
time engine
UI
routines
domains

Everything must feel unified.

10. FINAL EXECUTION STANDARD

If done correctly, the final product should feel like:

A calm, beautifully designed environment where the user simply flows from one action to the next without friction, overwhelm, or decision fatigue.

Not like:

an app
a planner
a dashboard system

But like:

a guided execution space.
