# Do It — The Spine

## What this app actually is
Adam isn't running parallel apps for his life domains. He's running **one life with many facets** — business, religion, learning, fitness, home, food, family. The app's job is to **make today coherent across all of them, in one place, with zero friction.**

Not a meal planner + gym planner + reader + prayer app. **One unified execution layer.**

## The unifying primitive: BLOCK
Every actionable thing in Adam's life is a Block. There is exactly one entity type for "thing to do." No separate "meal," "workout," "prayer task," "study session." All Blocks.

A Block has:
- `domain` (business / religion / learning / fitness / home / food)
- `duration` (minutes — elastic, never a timestamp)
- `title` (short)
- `step?` — optional "how to do it now" payload (recipe steps, workout sets, surah verses, lesson outline) — surfaced *inside NOW during execution*
- `visionId?` — what aim this serves
- `routineId?` — what rhythm this belongs to (recurrence lives here, not on the block)
- `meta?` — domain-specific extras (e.g. food blocks carry `ingredients[]` for shopping derivation)

## Surfaces are LENSES on blocks (no surface owns its own task list)

| Surface | Lens | Question answered |
|---|---|---|
| **NOW** | Single block in flight + its step iterator | "What am I doing this minute, and what's the next sub-step?" |
| **TODAY** | All blocks scheduled today, time-ordered, elastic | "What's the shape of today?" |
| **DOMAINS** | Blocks aggregated per domain → momentum signal | "How is each area of my life trending?" |
| **VISIONS** | Blocks aggregated per `visionId` → "am I aiming?" | "What am I building toward?" |
| **ROUTINES** | Blocks generated by routine cadence → streak/health | "What rhythms am I keeping?" |
| **MEAL** | Domain filter (food) + shopping derivation from `meta.ingredients` | "What am I eating + buying?" |
| **INBOX** | Unscheduled blocks captured by voice | "What did I capture?" |

**Tasks live in TODAY. Period.** Domains/Visions/Routines NEVER list tasks. They show signal, intent, rhythm.

## Core features (what the app DOES, ranked by value)
1. **Voice capture → block.** Hold-to-talk anywhere → block lands in inbox or scheduled. Auto-tagged with domain via keyword model. Zero typing.
2. **Step-by-step inside NOW.** Block carries a `step[]` payload — recipe steps, workout sets, surah verses. NOW shows current step + "done, next" button. The block executes itself.
3. **Elastic day.** No timestamps, only durations. Pause / resume / shift forward. Never "late" or "missed."
4. **Prayer anchors.** 5x/day hard anchors (Aladhan, Kiel, Hanbali). Day bends around them.
5. **Routines drive recurrence.** A Routine emits Blocks on its cadence. Streak/health is a property of the Routine, not the Block.
6. **Meal sub-feature.** Food blocks carry ingredients → shopping list auto-derives from upcoming food blocks. No separate meal planner data model.
7. **Vision linking.** Block.visionId → Vision page shows aggregated effort + intent statement. No progress bars. Calm signal only.
8. **Notion sync.** 4am pull seeds today's blocks from a Notion DB.
9. **Mid-execution capture without leaving NOW.** Voice → "add to next block" / "schedule tomorrow" / "queue in inbox" — never breaks focus.
10. **Domain momentum.** Per-domain calm words ("warm", "steady", "drifting", "humming") computed from recent block density. No numbers shown to user.

## Visual direction (locked)
- Premium iOS, playful, single focal object per screen, generous whitespace.
- Palette: white / pink / green / black / blue ONLY. Never purple/orange/yellow/red.
- Big rounded everything. Soft shadows. Hairlines.
- Subtle premium motion — no bouncy spring, no slide-up-from-bottom sheets EVER.
- Calm vocabulary throughout. "paused" / "adjusted" / "quiet" / "steady" — never "late" / "missed" / "failed" / "skipped."
- Topbar (greeting + memoji top-right) stays exactly as it is.

## What every subagent must NOT do
- Create a separate task list on Domains, Visions, or Routines.
- Add bottom-up sheets/drawers.
- Use any color outside the locked palette.
- Use guilt/failure vocabulary.
- Add information density — if in doubt, cut.
- Redesign the Topbar.

## Adam's mental model (informs features, not literal UI)
Adam approaches every domain through three modes: **Theory → Application → Feedback.** Reading a book is theory; doing a problem set is application; reviewing what stuck is feedback. Watching a workout video is theory; doing the lift is application; checking form is feedback.

→ Block gets an optional `mode: 'theory' | 'application' | 'feedback'` field. Surfaces don't force-segment by mode, but Domains can show a calm balance signal ("heavy on theory, light on application this week") to nudge balance.

## Goals with deadlines (extension of Visions)
Adam wants concrete deadlines: "I'll have X by date Y." Visions get an optional `deadline?: ISO-date` and an optional `targetMetric?: string` (free-text proof statement, e.g. "deadlift 180kg" or "shipped onboarding redesign"). Vision detail shows the deadline as a calm countdown in human language ("11 weeks out"), never as a red urgent bar. Past-deadline visions show "moved" not "missed" — Adam can extend with one tap.

## Today must be reorderable + show actual times
Durations stay primary (elastic), BUT TODAY also shows the projected start time of each block (computed live from the elastic engine + prayer anchors). Blocks are drag-to-reorder on TODAY. Reordering recomputes times instantly. Adam can tap a block and edit its specific duration; he never sets a timestamp directly.

## Routines = first-class
Routines are not a settings-buried list. They are a primary surface with depth:
- **Routine builder** (drag domains, set cadence in plain English, attach a step template that gets cloned into each emitted block).
- **Routine health** = streak phrase + "kept this week" + a small calendar dot grid showing the last 8 weeks (filled = kept, hairline = missed; never red).
- Routines emit Blocks at 4am into TODAY for that day.

## Money — financial overview surface
A first-class surface alongside Domains/Visions/Routines. Adam needs an at-a-glance view AND deep drill-down.

**Data:**
- `Subscription { id, name, amount, currency, cadence: 'monthly'|'yearly'|'weekly', nextChargeDate, category, note? }`
- `Transaction { id, kind: 'expense'|'income', amount, currency, date, category, note?, source?: 'manual'|'subscription' }`
- Categories are free-form tags (food, software, gym, rent, freelance-in, dividend-in, etc.)

**Surface — `MONEY`:**
- Top: calm overview — "this month: in 4,200 · out 2,810 · net +1,390" in plain language with subtle hairlines, no red/green flashing.
- Three drill-down cards: **Subscriptions** (sorted by next charge), **Outflow** (this-month expenses by category, calm bar), **Inflow** (this-month income by source).
- Tap any card → detail screen with full list, sortable, filterable by month / category / amount.
- Add transaction = bottom-of-screen affordance? NO — top inline strip (sheet rule applies).
- Calm vocab: never "overspending" / "broke" — use "spending heavy this month" / "running quieter than last month."

**MUST NOT:** red urgent colors, judgment vocabulary, surprise modal alerts about charges.

## Creative features that fit the spine (queued)

These extend the same Block primitive and the unified-life thesis. Each earns its place by feeding momentum, removing friction, or compounding insight.

1. **Reflections** — end-of-day prompt (voice-first): "what worked · what shifted · tomorrow's first move." Stored as `Reflection { date, worked, shifted, firstMove }`. Powers Yesterday screen, feeds Domain momentum, surfaces in Vision detail as "what you proved this week."

2. **State log** — one tap to log how Adam feels right now: `clear | focused | wired | drained | heavy`. Five words, no numbers. Surfaces patterns: "you tend to be drained after stacking 3 fitness blocks back-to-back."

3. **Insights** — capture a quote / line / lesson while learning, attached to a vision or domain. `Insight { text, source, domainId?, visionId?, capturedAt }`. Personal commonplace book. Surfaces in Vision detail as "what you're learning toward this."

4. **Weekly review** — Sunday auto-prompt with 5 calm questions, builds a one-pager. Adam's "elite at everything" loop requires this checkpoint.

5. **People** — relationship surface. `Person { id, name, relation, lastTouched, nextMove }`. Calm CRM for family, mentors, friends. "Call mom · 8 days quiet."

6. **Anchor stack on TODAY** — prayer windows render as soft tinted bands BEHIND the elastic block flow. Visible without blocking. Beauty + function.

7. **Compounder trend phrase** — across weeks per domain: "religion: warm → warm → humming." Word-trend, no numbers. "You've been steady on fitness for 6 weeks."

8. **Voice-driven mid-NOW commands** — hands-free during execution: "extend ten" · "pause" · "done" · "skip" · "queue inbox." No screen tap.

9. **Sleep + wake anchors** — bedtime + wake-up as soft anchors that bookend the day. First block = wake routine. Last = wind-down.

10. **PWA share target** — share article from Safari → block in inbox under learning domain. Zero-friction capture from anywhere.

## Routine cadence — week-of-month aware
Routines need richer cadence than Mon/Wed/Fri. Adam: "week one of the month has this routine, week two has another."

Routine.cadence becomes a structured rule:
```ts
type RoutineCadence =
  | { kind: 'weekly'; days: Weekday[] }                           // every week, on these weekdays
  | { kind: 'biweekly'; days: Weekday[]; anchorWeek: 'A'|'B' }   // alternating weeks
  | { kind: 'monthlyWeeks'; weeks: (1|2|3|4|5)[]; days: Weekday[] } // e.g. weeks 1+3 on Mon
  | { kind: 'monthlyDays'; days: number[] }                      // e.g. 1st and 15th of each month
  | { kind: 'interval'; everyDays: number; from: ISODate };       // every 3 days from a start
```
Routine builder UI must let Adam pick a cadence kind, then configure. Plain-English phrase derives automatically ("Mondays of weeks 1 and 3").

## Information architecture — thematic grouping (replaces flat 16-item nav)

Adam: "the way things are ordered, just how you navigate through it — supposed to be way more vast — this is part of UX."

Bottom nav (mobile) / sidebar rail (desktop) — 4 primary destinations only:
1. **NOW** — single focal block
2. **TODAY** — today's flow
3. **WEEK** — Mon-Sun arc view (the new weekly surface)
4. **MORE** — grouped index of every secondary surface

The "MORE" surface is itself a beautiful screen, not a dump. Surfaces are grouped by intent:

- **DO** — Inbox · Templates · Focus modes · Cmd+K
- **TRACK** — Habits · Health (Sleep/Hydration/Body) · Workouts · State log
- **KNOW** — Visions · Goals · Insights · Books · Brag book · Knowledge graph
- **LIFE** — People · Money (overview/subs/expenses/income) · Wishlist · Meal (planner/shopping)
- **TEND** — Domains · Routines · Reflect · Weekly Review
- **HOME** — Yesterday · Settings (memoji-tap shortcut still goes here)

Each group is a labeled section on the MORE screen with its surfaces as tappable tiles in the group. Calm typography for group labels (small uppercase + hairline divider).

Cmd+K (desktop) and a slide-from-right "all surfaces" search (mobile) provide instant access regardless of grouping.

## Anti-friction principles
- Voice capture must work from any screen, any time.
- Mid-NOW capture must not navigate away.
- Tap target minimum 44px.
- Every action reversible (no destructive without undo).
- Loading states are calm, not blocking.
